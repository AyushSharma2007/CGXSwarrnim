## SECTION – A (Objective Type)                                        [12 Marks]

### A1. Fill in the Blanks: (1 × 6 = 6 Marks)

1. A system that tracks changes made to files over time is called a ________________________.  
2. Git was created by ________________________ in the year 2005.  
3. The intermediate area between Working Directory and Local Repository is called the ________________________.  
4. The command used to upload local commits to GitHub is ________________________.  
5. Creating a personal copy of someone else’s repository on your own GitHub account is called ________________________.  
6. The file used to tell Git which files should not be tracked is named ________________________.

### A2. State whether the following statements are True or False: (1 × 6 = 6 Marks)

1. Git and GitHub are the same software.  
2. In a Distributed VCS, every developer has a complete copy of the repository history.  
3. `git commit` uploads the code to GitHub.  
4. A branch allows developers to work on features without disturbing the main code.  
5. `git stash` is used to permanently delete uncommitted changes.  
6. A Pull Request is mainly used for code review and controlled merging in team projects.

**B1.** What is the difference between Local Repository and Remote Repository?  

**B2.** Explain the purpose of the Staging Area in Git.  

**B3.** What is the difference between Clone and Fork?  

**B4.** Why should developers avoid working directly on the `main` branch?  

**B5.** What is a merge conflict? When does it usually occur?

## SECTION – C (Descriptive / Scenario Based)                       [16 Marks]

**Answer any TWO of the following:** (8 × 2 = 16 Marks)

**C1.** Explain the complete basic Git workflow with the help of the following stages:  
Working Directory → Staging Area → Local Repository → Remote Repository  
Also write the main command used at each stage.

**C2.** A student has created a project on his/her computer. The project is **not** yet a Git repository.  
Write the complete sequence of commands (with short explanation) to upload this project to GitHub for the first time.

**C3.** Explain the simple team collaboration workflow using GitHub:  
Create feature branch → Make changes → Commit → Push → Create Pull Request → Review → Merge → Update local main.  
Why is this workflow preferred in team projects?
